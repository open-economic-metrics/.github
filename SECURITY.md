# Security policy

## Reporting a vulnerability

Do **not** disclose an exploitable vulnerability, credential, or sensitive data through a public issue, pull request, or discussion.

For an affected repository that has private vulnerability reporting enabled, use **Security → Advisories → Report a vulnerability** in that repository. Include the affected version or revision, a concise reproduction, impact, and any mitigation you have tested. Limit any proof of concept to systems and data you are authorized to test.

If private vulnerability reporting is not available, use an explicitly published private maintainer contact channel. If no such channel exists, open a **non-sensitive** issue requesting a private reporting route, without including exploit details. A universal confidential reporting inbox has not yet been established.

## Scope and response

This organization is in its initial setup stage; no guaranteed response time or bug-bounty program is offered. Project-specific supported versions and disclosure timelines will be documented when published releases exist.

Security issues in third-party data providers, GitHub itself, or other organizations should also be reported directly to those parties through their designated processes.

Statistical inaccuracies and methodological disputes are not automatically security vulnerabilities; use an issue unless they involve an exploitable security or confidentiality risk.
